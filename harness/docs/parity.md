# Python to TypeScript parity manifest

This manifest classifies every externally observable behavior in
`apps/pipeline/src/pipeline`. Exact differential tests apply only to `preserve` rows. A `change`
row names the correcting design decision and its normative TypeScript test. A `retire` row names
why no TypeScript consumer remains.

`__init__.py` contains only the package docstring (`"Pipeline app."`) and has no executable or
artifact behavior to classify. Every other Python module is covered below.

The differential black-box boundary is drift and diagnosis, the genuinely shared Python and
TypeScript surfaces. A raw-trace/provider differential is not defined because Python has no
equivalent surface; the existing TypeScript raw-trace/stub-provider end-to-end test covers that
TypeScript-only path. Remediation is also outside the differential boundary because its move
from local-file mutation to a GitHub-branch operation is classified as `change` and enforced by
normative TypeScript tests.

The Python-subprocess differential tests and CI `uv` setup retire together with Python during
Phase E3 of the build plan.
The manifest, TypeScript golden canonicalization vectors, and normative tests survive the
cutover.

## Boundary findings

The requested raw-trace/provider black-box has no non-empty preserve projection:

| ID  | Classification | Behavior and justification                                                                                                                                                                                                                        | Enforcement                                                                                          |
| --- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| BB1 | change         | Python has no raw-trace adapter, provider client, or replay transport; its public boundary starts at a historical bundle or prebuilt candidate results. TypeScript owns `ingest` through `replay`, per Architecture sections 4 and 6.             | `e2e.test.ts` — `runs end to end, reports both families, resumes replay, and never persists the key` |
| BB2 | change         | Python final output is per-case `terminal_verdict` plus `standard-benchmark`; TypeScript selects on one split, confirms on holdout, and emits per-family `recommend`, `reject`, `abstain`, or `inconclusive`, per Architecture sections 7 and 10. | `selection.test.ts` — `does not select a holdout winner that fails a binding release gate`           |
| BB3 | change         | Python passes through reviewer-supplied case IDs; TypeScript case IDs are RFC 8785 content digests. Injecting the TypeScript ID into Python input would be tautological rather than parity.                                                       | `data.test.ts` — `is content deterministic and persists normalized stratum weights`                  |
| BB4 | change         | Python turns missing results into case abstentions and has no exclusion fields; TypeScript reports excluded executions/fraction and a worst-case-imputed bound, per Architecture section 7.                                                       | `aggregation.test.ts` — `excludes ambiguous and lost executions and publishes a worst-case bound`    |

The differential suite below therefore covers the field-preserving drift and diagnosis
boundary. Intentional differences remain classified as `change` and pinned by normative tests.
