`portkey/` holds three real responses of the open-source Portkey gateway 1.15.2 (`portkeyai/gateway:1.15.2`, digest `sha256:97f094d9c8a764cbfaa2a7138c0017b247ca923bb06db1b4c13b7f8a33b5200d`), captured on 2026-09-23 against a local echo upstream that answers with the requested model: `plain.json` (provider headers only; the stock image reports `x-portkey-cache-status: DISABLED`), `override-params.json` (a config whose `override_params` changes the model) and `input-mutator.json` (a config whose `default.addPrefix` mutator reports `transformed: true`). Each file keeps the requested model, the status, the `x-portkey-*` and `content-type` headers, and the body. `capture.sh` is the capture: it starts `echo-upstream.mjs` and the pinned image and sends the same request once per configuration, with the provider headers for `plain.json` and an `x-portkey-config` header for each of the other two. Run again on 2026-09-24, it returned the same three responses apart from timestamps, execution times and the generated hook id.

`envoy/` holds two responses of the open-source Envoy AI Gateway (renamed Agent Router) v1.1.0, `envoyproxy/ai-gateway-cli:v1.1.0` (`sha256:df69760bb46b6dcb8e9c6cc3cbf040d02e1b970dab05568c478fdcc418d144b6`), captured on 2026-09-23 through `aigw run` against Vercel AI Gateway: `plain.json` (the upstream's answer passed through unchanged, naming the requested model) and `fallback.json` (a route whose priority-0 backend failed, answered by its priority-1 backend under `modelNameOverride`, so the body names a model other than the requested `fallback-demo`). `capture-config.mjs` writes the `aigw run` configuration the capture ran, calling `../gateway-acceptance/envoy/aigw-config.mjs` with the capture's models and fallback route, and `mock-500.mjs` is that route's priority-0 backend, which answers every request with HTTP 500.

`bifrost/` holds two responses of the open-source Bifrost gateway transports/v2.2.1, `maximhq/bifrost:v2.2.1` (`sha256:a8942692af7b4b89196cd8fc33653b7353488dfd58b24078fe793b8574a8084b`), captured on 2026-09-24: `chat.json` (a call to `vercel/amazon/nova-micro` through Vercel AI Gateway configured as an OpenAI-typed custom provider with every compat flag off, answered with the provider prefix stripped, `amazon/nova-micro`, and the upstream's billed cost as the object `usage.cost.total_cost`) and `compat-drop.json` (a `response_format` request to `openrouter/amazon/nova-micro-v1`, a native OpenRouter model that does not list structured output, with the compat flags left at their defaults, so the compat plugin dropped `response_format`, answered 200 and reported it in `extra_fields.dropped_compat_plugin_params`). Each file keeps the requested model, the status, the `x-bifrost-*` and `content-type` headers, and the body. `chat.json` was captured under `../gateway-acceptance/bifrost/config.json`, and `compat-drop.json` under `compat-drop-config.json`: the same file with the client's `compat` block removed and OpenRouter added as a native provider.

`source-derived.json` holds markers the stock images cannot produce locally, written from the pinned vendor source cited in each entry's `source` field, not captured: Portkey's cache status header (caching is compiled out of the stock image) and Bifrost's `extra_fields` markers.

## Reproducing the gateway evaluation pitfalls

Each row is one way a gateway can return a response that is not a fresh answer from the requested model to the request as sent. Fixture paths are relative to this directory; `../traces/` is `harness/fixtures/traces/`. Hermetic stub tests are named by their `it` title, in `harness/packages/replay/src/provenance.test.ts` unless another file is named; the two trace reader tests are in `harness/packages/rightmodeler/src/data/adapters/`, and the live provider tests in `harness/packages/rightmodeler/src/`. The provenance tests need no build, network or keys; the trace reader tests need the workspace packages built:

```sh
pnpm install --frozen-lockfile
pnpm --filter @rightmodeler/replay exec vitest run src/provenance.test.ts
pnpm exec turbo run build --filter=@rightmodeler/cli
pnpm --filter @rightmodeler/cli exec vitest run src/data/adapters/openinference.test.ts src/data/adapters/bifrost.test.ts
```

The live provider tests run the built CLI against the pinned images, so they need the build above, a running Docker, and a Vercel AI Gateway key in `AI_GATEWAY_API_KEY`; without `RIGHTMODELER_LIVE_GATEWAYS=1` they skip and print the reason. Each replay leg runs under a spend cap of $0.25, and each leg that forces another model under $0.10.

```sh
RIGHTMODELER_LIVE_GATEWAYS=1 pnpm --filter @rightmodeler/cli exec vitest run \
  src/gateway-portkey.live.test.ts src/gateway-envoy.live.test.ts src/gateway-bifrost.live.test.ts
```
