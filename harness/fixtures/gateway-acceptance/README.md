The gateway acceptance kit drives the opt-in live gateway tests (`harness/packages/rightmodeler/src/gateway-*.live.test.ts`, run with `RIGHTMODELER_LIVE_GATEWAYS=1`, Docker, and `AI_GATEWAY_API_KEY`). The plan-routes live test (`src/plan-routes.live.test.ts`, run with `RIGHTMODELER_LIVE_PLAN_ROUTES=1`, `RIGHTMODELER_LIVE_PLAN_DIR` and `AI_GATEWAY_API_KEY` on a machine where `claude` and `codex` are signed in) reuses `app/` and `capture.mjs` with pinned incumbents for its two plan legs. `app/summarize.mjs` is a two-call-site application the scanner reads; the test replaces `__MODEL_A__` and `__MODEL_B__` with two models it discovers live, commits the copy in a throwaway repository, and never runs it. `capture.mjs` sends short chat completions through a gateway and, with `--out`, writes them as OpenAI SDK JSONL. `envoy/aigw-config.mjs` writes the standalone `aigw run` configuration for the models a test declares, and `envoy/collector.yaml` configures the OpenTelemetry collector that writes the gateway's spans to a file. `bifrost/config.json` is the replay-safe Bifrost configuration (every compat flag off, Vercel AI Gateway as an OpenAI-typed custom provider, request logging on), and `bifrost/export-logs.mjs` writes every chat completion in a running Bifrost's log store as one `GET /api/logs/{id}` detail per line. `discoverLiveModels()` reads the public Vercel AI Gateway catalog at run time, so no model is pinned. Every model it picks is a priced language model with text output that accepts `temperature`, lists no `reasoning` parameter (a reasoning model can spend the capture's 64 output tokens before it answers) and is not a `-fast` service tier (Vercel answers those under the base model's id, which the served-model check counts as a substitution); incumbents and candidates also accept `tools` and `response_format`. The incumbents are the two median-priced such models of the vendor with the most, the candidates the three cheapest of the next vendor that are cheaper than both incumbents, and the judges the two cheapest of a third vendor. Containers are named `rm-gw-accept-*`, bind 127.0.0.1 on ports 18000 to 18999, and are removed after each test; every file a test writes is scanned for the key before it finishes.
